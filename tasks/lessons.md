[2026-05-17] | D4 keying unification (clip_code → clip_details_code) shipped in 4 commits because the first attempt only updated producers and lookups, then the second pass missed the per-consumer map POPULATION sites, then a third pass missed the JSX RENDERING sites. Two regressions surfaced over two browser verification cycles. | Keying contract has FOUR sweeps, not three: (1) PRODUCER (db function `map.set(key, ...)`), (2) LOOKUP (`totalsMap[key]`), (3) POPULATION (consumer useEffect `map[key] = t`), (4) RENDERING (JSX `{post.clip_code}` labels). When changing a key strategy, grep ALL four classes in the same audit. The rendering sweep is the easiest to skip because it doesn't break tests — it just shows wrong labels. Use shared helpers (`clipKey()`, `displayClipCode()`) so the contract is enforced by import, not by discipline.

[2026-05-18] | Scheduled diagnostics-alert cron returned 401 from its secondary fetch to `/api/diagnostics` while manual curl from a local terminal succeeded. Root cause: Vercel cron routes scheduled invocations to a protected alias domain (Protect Cron Jobs); the primary request bypasses via Bearer CRON_SECRET, but a bare secondary fetch back to `${origin}` hits the same protected alias with no Bearer and gets the HTML auth wall. Manual curls work because they hit the public production URL, not the protected alias. | Always propagate `Authorization: Bearer ${process.env.CRON_SECRET}` on cross-route fetches inside Vercel crons when deployment protection is enabled.
